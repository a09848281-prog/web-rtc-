# セットアップ手順（Firebase不使用・RTC待機方式）

## 1. GASを更新する（必須）

GASは最初のペアリングとSDP/ICE交換（初回・再接続）だけに使用します。RTC DataChannelが開いた後は、通常操作でGASへ接続要求を問い合わせません。

1. GitHubの [gas/Code.gs](https://github.com/a09848281-prog/web-rtc-/blob/main/gas/Code.gs) を開き、全内容をコピーします。
2. 使用中のGoogle Sheets → 拡張機能 → Apps Scriptを開きます。
3. 既存の Code.gs を全置換して保存します。
4. 関数一覧から setup を選び、1回実行します。Devicesにブラウザ用トークンハッシュ列、Signalsにシグナリングの有効期限列を用意します。
5. デプロイ → デプロイを管理 → 鉛筆アイコン → バージョン「新バージョン」→ デプロイ。
6. 初回デプロイの場合は「実行ユーザー: 自分」「アクセスできるユーザー: 全員」に設定します。端末トークンで操作を認証します。
7. 既存のWebアプリURLをそのまま使用します。

**重要：旧バージョンで登録したAndroidは新しいブラウザ用アクセスキーを持っていません。** 新方式ではWeb画面で新しい登録コードを発行し、Androidを再ペアリングしてください。旧端末行はSheetsに残りますが、新しいブラウザの端末一覧には表示されません。

## 2. GitHub Pages

1. リポジトリ Settings → Pages → Sourceを「GitHub Actions」にします。
2. Actionsで「Deploy WebRTC Security Camera Web」が成功するのを確認します。
3. [WebRTC Security Camera](https://a09848281-prog.github.io/web-rtc-/) を開きます。
4. GAS URLは web/config.js に設定済みです。通常は入力不要です。
5. 古い画面が表示される場合はブラウザを再読み込みし、PWAをホーム画面に追加済みなら一度終了して開き直してください（キャッシュはv2に更新しています）。

## 3. Android APK

1. GitHubの [Actions](https://github.com/a09848281-prog/web-rtc-/actions) を開きます。
2. 最新の「Build WebRTC Security Camera APK」の成功実行を開きます。
3. Artifactsの webrtc-security-camera-debug-apk をダウンロードし、ZIPを展開します。
4. app-debug.apk をGalaxy A22 5GなどのAndroid端末へ転送してインストールします。
   - 署名エラーが出る場合は旧アプリをアンインストールして再インストールします。アンインストールすると端末トークンが消えるため、新しい登録コードで再ペアリングしてください。
5. Webで「Androidを新規登録」を押し、表示された6桁コードをAndroidアプリに入力して登録します。
6. Androidでカメラ・マイク・通知の権限を許可し、「バックグラウンドで待機開始」を押します。常時通知が表示されたらRTC待機準備中です。

## 4. Webから接続する

1. Androidの待機開始後、Web画面を開き、登録済みAndroid端末を選択します。
2. 「接続・映像開始」を押します。最初のRTC接続ではGASでOffer/Answer/ICEを交換します。
3. RTC DataChannelが開いたら、Webからの映像開始・停止、カメラ切替、モード変更、状態取得、PTT制御はRTC DataChannelへ送ります。通常待機中のコマンド確認にGASは使いません。
4. Webマイクを使う場合は「マイクを許可」を押し、ブラウザの許可を与えてください。PTTボタンを押している間だけWebマイクをAndroidへ送信します。
5. 「映像・音声を切断」はカメラ・マイクだけを停止し、RTC待機接続を残します。待機そのものを終了する場合はAndroidの常時通知にある「待機を終了」を押します。

## 5. 接続方式と制限

- Firebase / FCMは使用しません。
- GASはペアリングと初回/再接続時のSDP/ICE交換だけに利用します。
- RTCが接続されていない状態では、WebRTC DataChannel自体がまだありません。したがって最初の接続応答を受け取るためのシグナリング確認は必要です。RTCが確立した後はGASの定期ポーリングを停止します。
- Webページを閉じるとブラウザ側PeerConnectionも終了します。Androidは切断を検出して新しいOfferを用意し、次回のWeb接続時にはGASシグナリングで再接続します。
- 映像・音声はWebRTCで直接通信し、GASは映像・音声を中継しません。
- 既定ではGoogle STUNを利用します。STUNだけでは接続できないネットワークもあり、その場合は別途TURNサーバーと安全な認証情報配布が必要です。TURNサーバーは同梱していません。

## 6. AndroidのOS制限・安全性

- Androidのカメラとマイクはwhile-in-use権限です。待機開始はアプリ前面で利用者が操作し、カメラ・マイク権限を許可した状態でForeground Serviceを開始します。
- 待機中はカメラ・マイクのCaptureを開始しません。Webから指令を受けた場合に利用を試みます。
- AndroidのOS・端末メーカーがバックグラウンドでのカメラ/マイク開始を拒否した場合は、通知からアプリを開く必要があります。OS制限を回避する実装は行いません。
- 画面ロック後の接続継続は実機検証が必要です。強制停止、電源OFF、通信圏外では遠隔接続を保証しません。
- 録画・録音ファイルは作りません。映像・音声はリアルタイム転送です。

## 7. 認証・保管

- 6桁ペアリングコードは10分で失効し、一度だけ使用できます。
- Android用トークンとブラウザ用アクセスキーのハッシュをSheetsに保存します。ブラウザ用キーは発行元ブラウザのlocalStorageに保存します。
- ブラウザのlocalStorageを消去すると、そのブラウザから端末へアクセスできなくなります。再ペアリングしてください。
- GASのデプロイはGitHub更新だけでは反映されません。必ずApps Scriptに貼り付けて保存し、新しいバージョンをデプロイしてください。
